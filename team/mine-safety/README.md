# Модуль `mine-safety`

Конкурсный модуль моделирует безопасность подземной шахты поверх штатного контура OpenEgiz. Один Python-процесс содержит детерминированную модель вентиляции и риска, генератор телеметрии, MQTT-публикатор, HTTP API и локальный интерфейс оперативной карты.

## Архитектура

```text
setup_twins.py ──HTTP PUT──> Eclipse Ditto (26 двойников)

model.py ──> app.py ──MQTT opentwins events──> Telegraf ──> InfluxDB ──> Grafana
                │                                                       │
                └──HTTP API и 2D-карта──────────────────────────────────┘

make smoke ──MQTT──> Ditto ──MQTT──> Telegraf ──> InfluxDB
```

- `twins.json` — декларативный контракт 26 двойников.
- `setup_twins.py` — идемпотентная загрузка родительских и дочерних объектов.
- `model.py` — топология, нормальные диапазоны, сценарии, чистая оценка риска и 10-минутный прогноз советника.
- `app.py` — двухсекундный цикл, публикация истории в штатном формате событий `opentwins`, HTTP API и static UI.
- `static/` — русскоязычная SVG-карта без CDN и внешних скриптов.
- `dashboard.json` — provisioned dashboard Grafana с картой и историей InfluxDB.
- `compose.yml` — overlay с one-shot setup, сервисом и mount dashboard.
- `smoke_test.py` — публичная HTTP-проверка инвентаря, периода, сценариев и reset.

## Инвентарь и топология

Всего создаются 26 двойников: шахта, пять зон, три вентилятора, пять датчиков, 10 обезличенных работников и две единицы техники. Направленный граф приточного воздуха:

```text
shaft → main_drift → section_a
                   → section_b
                   → refuge_chamber
```

Главный вентилятор расположен в `shaft`, вспомогательные — в `section_a` и `section_b`. Погрузчик находится в участке A, транспорт — в участке B. Расположение работников фиксировано в модели для воспроизводимого расчёта затронутых людей.

## Запуск

Из корня репозитория:

```bash
make up
make smoke
```

Корневой Makefile всегда подключает `team/mine-safety/compose.yml`. На Windows при `OS=Windows_NT` дополнительно подключается базовый Windows overlay. Сервис доступен по адресу `http://127.0.0.1:8091/`, dashboard — в Grafana под именем **Безопасность подземной шахты**.

Локальные unit-тесты без Docker:

```bash
python -m unittest discover -s team/mine-safety/tests -p "test_*.py"
python -m compileall -q team/mine-safety
```

Smoke-тест уже запущенного конкурсного сервиса:

```bash
python team/mine-safety/smoke_test.py --base-url http://127.0.0.1:8091
```

## Публичный HTTP API

| Метод и путь | Назначение | Тело запроса |
|---|---|---|
| `GET /health` | Готовность, MQTT и период публикации | Нет |
| `GET /api/state` | Полный текущий снимок шахты | Нет |
| `POST /api/scenarios/main_fan_failure` | Отказ главного вентилятора | Пустой JSON-объект |
| `POST /api/scenarios/methane_release` | Выброс метана | JSON с `zone` равным `section_a` или `section_b` |
| `POST /api/scenarios/fire` | Пожар | JSON с `zone` равным `main_drift`, `section_a` или `section_b` |
| `POST /api/scenarios/blocked_working` | Перекрытие выработки | JSON с `zone` равным `section_a` или `section_b` |
| `POST /api/reset` | Полный возврат в нормальный режим | Пустой JSON-объект |

Пример для Bash:

```bash
curl -fsS -X POST -H 'Content-Type: application/json' \
  -d '{"zone":"section_a"}' \
  http://127.0.0.1:8091/api/scenarios/methane_release

curl -fsS -X POST -H 'Content-Type: application/json' \
  -d '{}' http://127.0.0.1:8091/api/reset
```

Одновременно активен один сценарий. Команда сценария немедленно обновляет публичный снимок и публикует его в MQTT; фоновый цикл продолжает работу каждые 2 секунды. Блок `finally` smoke-теста всегда пытается выполнить reset.

## Модель данных

`GET /api/state` возвращает:

- `timestamp`, `tick`, `simulated_seconds`, `publish_interval_seconds`;
- `scenario` и `incident` с источником, уровнем, причинами и рекомендациями;
- `topology` и `airflow` с активными направленными связями;
- `sensors` для пяти зон;
- `fans`, `workers`, `equipment`;
- `risk` с оценкой по зонам, затронутыми зонами и людьми;
- `ventilation_advisor` с режимом, целевыми скоростями вентиляторов, действиями и двумя прогнозными траекториями;
- `fan_energy` с текущей и рекомендуемой мощностью, энергией/стоимостью за 10 минут и сравнением с режимом 100%;
- `evacuation_plan` со сгруппированными маршрутами затронутых работников, пунктами назначения, временем и блокировками;
- `assumptions` с порогами и предупреждением о демонстрационном назначении.

Setup создаёт и инициализирует все 26 двойников через Eclipse Ditto. Для исторических графиков `app.py` каждые 2 секунды публикует сводку `mine-01` и пять датчиков в том же формате событий `opentwins`, который выдаёт Ditto. Telegraf сохраняет feature values в bucket `default`, measurement `mqtt_consumer`, а Grafana читает их через provisioned datasource `opentwins-influxdb`. Такой канал не создаёт постоянную очередь команд `modify` в Ditto на ноутбуке с ограниченной памятью; отдельный `make smoke` по-прежнему проверяет полную цепочку MQTT → Ditto → MQTT → Telegraf → InfluxDB.

## Диапазоны и пороги

| Метрика | Нормальный диапазон | Предупреждение | Критический уровень |
|---|---:|---:|---:|
| `methane_pct` | 0,08–0,45 % | 1,0 % | 2,0 % |
| `co_ppm` | 2–8 ppm | 25 ppm | 50 ppm |
| `smoke_index` | 0–0,05 | 0,2 | 0,5 |
| `temperature_c` | 18–25 °C | 35 °C | 50 °C |
| `airflow_mps` | 1,3–3,5 м/с | 0,8 м/с и ниже | 0,3 м/с и ниже |

Нормальный шум зависит только от seed, номера тика и зоны. Одинаковые входные показания, топология и расположение людей дают одинаковые уровень риска, причины и рекомендации. Повторный запуск процесса использует seed из `MINE_SAFETY_SEED`, по умолчанию 42.

## Логика сценариев

- `main_fan_failure` останавливает главный вентилятор и снижает поток во всей шахте.
- `methane_release` устанавливает опасную концентрацию метана только в выбранном добычном участке.
- `fire` повышает CO, дым и температуру в источнике и вниз по активному графу воздуха с убыванием по расстоянию.
- `blocked_working` отключает связь `main_drift` с выбранным участком и создаёт низкий поток в нём.

Риск каждой зоны — максимальная серьёзность нарушенного порога. Общий риск — максимальный риск зон. Затронутыми считаются работники, чьи фиксированные зоны попали в список опасных. Рекомендации дедуплицируются и объясняют наблюдаемые причины.

## Советник по вентиляции

Советник пересчитывается вместе с каждым снимком и сравнивает точки 0, 2, 4, 6, 8 и 10 минут для двух вариантов: продолжение сценария без действий и гипотетическое выполнение совета. Для каждого варианта API возвращает уровень риска, список затронутых зон, число людей, максимум CH₄ и CO и минимальный поток воздуха. Отдельно выдаются целевые проценты `fan-main`, `fan-aux-a`, `fan-aux-b` и последовательность ручных действий.

В норме советник сохраняет режим 100/75/75. При отказе главного вентилятора он рекомендует восстановление главного потока и готовность вспомогательных вентиляторов; при метане — изоляцию участка и усиленное местное проветривание; при перекрытии — восстановление ветви; при пожаре — локализацию дымовой ветви с сохранением подпора к эвакуационной камере. Источник пожара в прогнозе остаётся критическим: модель не подменяет эвакуацию обещанием автоматического устранения аварии.

## Энергетика вентиляторов

Модуль `fan_energy` связывает рекомендации советника с оценкой энергопотребления. Демонстрационные паспортные мощности: 180 кВт для `fan-main` и по 45 кВт для `fan-aux-a` и `fan-aux-b`. Для частотно-регулируемого привода применяется прозрачное приближение `P = Pном × (скорость / 100)³`. Тариф задан как 30 ₸/кВт·ч.

Для текущего и рекомендуемого режимов рассчитываются мощность, энергия и стоимость за 10 минут. Дополнительно показываются экономия мощности и суточный потенциал относительно постоянной работы всех трёх вентиляторов на 100%. Эти значения являются сравнительной оценкой: модель не учитывает КПД двигателя, давление сети и реальные тарифные зоны. При аварии безопасный рекомендуемый режим имеет приоритет, даже если он потребляет больше текущего.

## Маршруты эвакуации

Для работников в затронутых зонах `evacuation_plan` строит путь к стволу или эвакуационной камере по активным связям. Перекрытые рёбра исключаются. Опасные транзитные зоны штрафуются, а безопасная конечная точка имеет приоритет над коротким маршрутом. Работники группируются по исходной зоне; для группы выдаются путь, пункт назначения, статус `safe`, `caution` или `blocked`, список работников и оценка времени из допущения 1,5 минуты на одну связь.

На карте путь выделяется поверх воздушных связей, условный маркер движется к точке сбора, а недоступный выход обозначается красным знаком в исходной зоне. При включённом системном режиме уменьшения движения анимация отключается. План является только рекомендацией: он не перемещает цифровые двойники работников и не запускает реальную эвакуацию.

## Допущения и ограничения

- Данные полностью синтетические; реальные персональные и конфиденциальные данные отсутствуют.
- Пороги демонстрационные и не являются нормативами промышленной безопасности.
- Граф не моделирует сопротивление, утечки, рециркуляцию и переходную аэродинамику.
- Прогноз советника — детерминированная демонстрационная экстраполяция на 10 минут, а не CFD или машинное обучение.
- Энергетика использует демонстрационные паспортные мощности, кубическую зависимость и фиксированный тариф, а не данные коммерческого учёта.
- Маршрут использует упрощённый граф и фиксированные 1,5 минуты на связь без учёта уклона, плотности потока, дверей и индивидуальной мобильности.
- Расчёт предназначен для воспроизводимой демонстрации, а не для инженерного проектирования.
- Система только рекомендует действия и не управляет оборудованием или эвакуацией.
- Текущее состояние сценария хранится в памяти и после перезапуска возвращается в норму.
- Интерфейс получает оперативный снимок напрямую; исторические точки InfluxDB могут появляться с задержкой около 10 секунд.
- Поток истории публикуется в шину `opentwins` напрямую, а не записывает все шесть объектов в Ditto каждые 2 секунды; актуальное состояние для карты доступно через HTTP API, наличие двойников и полный маршрут через Ditto контролируются smoke-тестом.
- HTTP и Grafana опубликованы на loopback-интерфейсе для локального стенда.
